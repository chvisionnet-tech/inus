# /inus-audit

입력 인자: $ARGUMENTS

## 0. 인자 처리 (먼저 판정)
- 인자가 비었거나 `도움말`: 아래 명령표만 보여주고 **끝낸다**. 에이전트·점검을 실행하지 않는다.
- `사전점검`: 1단계만 하고 끝낸다.
- `수정범위`: 직전 점검 결과(이 세션, 없으면 `~/inus-audit-reports/` 최신 파일)로 6단계만 한다. 결과가 없으면 점검부터 하라고 안내하고 끝낸다.
- 영역명·`교차`·`전체`: 1단계부터 순서대로 한다.

| 명령 | 하는 일 |
|---|---|
| `/inus-audit 도움말` | 이 명령표 |
| `/inus-audit 사전점검` | 브랜치·소스 존재·인코딩·키 노출 1차 스캔·대형 파일 분할 계획 (에이전트 안 띄움) |
| `/inus-audit 결제` | 결제 영역만 |
| `/inus-audit 로그인` | 로그인·인증·서명·한도 |
| `/inus-audit 메인gas` · `영업gas` | 해당 GAS 프로젝트 |
| `/inus-audit ai중계` | GPT 중계·모델 매핑·폴백 |
| `/inus-audit vba엔진` | 미니창 엔진(ModFollowUp1~4) |
| `/inus-audit 동기화` | 영업상태 공유 목록·신호파일·시트 쓰기 |
| `/inus-audit 홈페이지폰` | s·route·leader.html, _worker.js, 폰 앱 |
| `/inus-audit 교차` | 키 노출·부하·백업·개인정보·업데이트 무결성·날짜 경계 |
| `/inus-audit 전체` | 위 전부 (비용 큼, 확인 후 진행) |
| `/inus-audit 수정범위` | 점검 결과로 수정 소유권·순서표 작성 |

## 1. 사전점검 (하나라도 실패하면 중단하고 이유를 알린다)
1. 저장소 루트에서 실행: `cd "$(git rev-parse --show-toplevel)" && python3 .claude/skills/inus-audit/prep.py` (Windows는 `py` 또는 `python`). 파이썬이 없으면 설치를 안내하고 중단한다.
2. 출력을 읽는다. `[중단]`이면 `src/README.md`를 안내하고 끝낸다. 소스가 없는 영역은 "확인불가"로 두고 건너뛴다.
3. `[경고]` 처리: 미커밋 변경이 있으면 정리 후 진행하자고 권한다(에이전트의 파일 수정 감지가 흐려짐). 원격보다 뒤처졌으면 `git pull`을 권한다.
4. 에이전트 도구(Agent)를 못 쓰는 환경이면 영역을 하나씩 직접 순서대로 점검한다(결과 형식은 같다).
5. 실행 계획을 한 줄로 알린다: 영역 n개 · 에이전트 n개 · 대형 파일 분할 n조각 · 비용 작음/중간/큼.
   - 영역을 명시한 명령(예: `/inus-audit 결제`)은 확인 없이 진행한다.
   - `전체`·`교차`이거나 사용자가 명령을 직접 쓰지 않았으면 **반드시 먼저 확인**한다.

## 2. 원칙
1. 에이전트는 이 대화를 모른다. 브리프에 목표·범위·찾을 것·보고 형식을 모두 적는다.
2. 읽기 전용. 에이전트 종류는 general-purpose를 쓰고 브리프에 "파일을 수정·생성하지 말 것"을 적는다. (Explore는 발췌만 읽는 검색용이라 점검에는 쓰지 않는다.)
3. 증거 없는 판정은 무효다. 파일·**함수명**·원문 한 줄이 필요하다.
4. "확인불가"를 허용한다.
5. 범위 밖 의심은 "교차 확인 요청"에만 적고 직접 읽지 않는다.
6. [치명]은 조율자가 원문을 직접 열어 재확인한 뒤에만 수정 대상으로 올린다.
7. 수정은 조율자만, 파일·함수 단위로 소유자 1명.
8. 비밀값은 보고에 마스킹(앞 4자 + ***). 원문 키를 대화·보고서에 적지 않는다.

## 3. 영역 지도와 대상 파일
파일은 `audit_work/plan.json`(사전점검이 만든 계획)의 `work` 경로(UTF-8 변환본)를 읽게 한다. 원본 경로로 보고하게 한다.

| 영역 | 대상 | 중점 |
|---|---|---|
| 결제 | 메인 GAS 결제 부분, VBA 결제창·결제 신호 | 중복 처리, 상태 꼬임, 서명·위변조 확인, 실패 복구 |
| 로그인·인증 | 서명 확인, 폰 키, 1인 한도, 그룹 권한 | 서명 우회, 키 노출, 토큰 만료 |
| 메인 GAS | `src/gas-main/` | 속성 읽기·쓰기 횟수, try 밖 호출, 한도, 락 안 외부호출 |
| 영업 GAS | `src/gas-sales/` | 시트 행 증가, 락 없는 동시 쓰기 |
| AI 중계 | VBA 중계 함수, GAS 중계, `src/worker/` | 빈 응답 폴백, 태그 누락, 직접 호출, 모델명 하드코딩 |
| VBA 엔진 | `src/vba/` ModFollowUp1~4 | 타이머 중복, 신호파일 삭제, 창 중복, 모듈 줄수 |
| 동기화 | 영업상태 txt, 시트 쓰기, ModMobileSync | 동시 저장 충돌, 읽기 실패 시 삭제 |
| 홈페이지폰 | `site/`, `src/worker/` | 캐시 번호, 옛 호환 깨짐, 목록 토큰 |
| 교차 | 전 영역 | 키 노출, 부하 하루 합계, 백업·복구, 개인정보, 업데이트 무결성, 날짜 경계 |

대형 파일(plan.json의 chunks가 2개 이상)은 조각마다 에이전트를 나눈다. 한 에이전트에 3,000줄을 넘기지 않는다. `midcut: true` 조각은 경계 프로시저를 앞뒤 조각이 함께 읽게 한다.
한 번에 띄우는 에이전트는 **최대 8개**. 초과분은 2차 배치로 돌린다. 결제·로그인은 "기능이 맞나"와 "악용·실패 시 어떻게 되나"를 따로 보는 2개 관점을 붙일 수 있다(전체 점검에서만).

## 4. 브리프 템플릿
```
[목표] <영역/조각>에서 오류·함정·결함을 찾아 보고. 파일을 수정·생성하지 말 것.
[먼저 읽기] 저장소 루트 CLAUDE.md 의 "코드 규칙 요약" 절.
[범위] <work 경로>의 <from>~<to>줄. 색인은 audit_work/index/<경로>.idx.txt. 이 밖은 읽지 말 것.
[읽는 법] 파일 전체를 한 번에 읽지 말고 색인과 grep 으로 좁힌 뒤 해당 함수만 읽는다.
[찾을 것]
- <영역 중점 항목>
- 규칙 위반 잔재: 창 내부 모달 대신 alert/MsgBox/confirm, 한글 ChrW 변환, Open For Output 직접 쓰기, .Visible 로 HTA 판단, 1024자 초과
[보고 형식] 최대 15건(나머지는 건수만)
- 위치: 원본 경로 / 함수명 / 줄(변환본 기준 참고용) / 원문 한 줄
- 실패 시나리오: 어떤 상황에서 무엇이 틀어지는지 한 줄
- 등급: [치명] 먹통·데이터 손실·보안 / [주의] 조건부 / [개선]
- 확인: 확인됨 / 확인불가(이유)
- 비밀값은 마스킹. 없으면 "치명·주의 없음" 한 줄.
[교차 확인 요청] 범위 밖 의심은 여기에만.
```

## 5. 실행 후 안전 확인 → 취합 → 재확인
1. 에이전트가 끝나면 `git status --porcelain`을 본다. `audit_work/` 밖에 변경이 있으면 에이전트가 파일을 건드린 것이다. 사용자에게 알리고 되돌릴지 묻는다(임의로 되돌리지 않는다).
2. 같은 함수를 가리키는 중복을 합친다. 함수명이 위치의 기준이다(내보낸 파일 줄 번호는 VBA 편집기와 다르다: 머리말 줄 차이).
3. 영역끼리 이어지는 결함을 찾는다(예: 결제 상태 ↔ 토큰 만료, 영업 GAS 쓰기 ↔ 메인 GAS 한도). 부하는 영역별 숫자를 모아 하루 합계로 다시 계산한다.
4. [치명]은 원문을 직접 연다. 틀렸으면 등급을 내린다.
5. 보고서는 `~/inus-audit-reports/날짜-영역.md`에 저장한다. **저장소 안에 두거나 커밋하지 않는다**(저장소가 공개일 수 있고, 보안 결함 목록이 노출된다).

## 6. 수정 범위 확정 (충돌 방지)
| 수정 대상(파일·함수) | 소유 | 선행 | 이유 |
|---|---|---|---|
- 공용 함수(여러 영역이 호출)는 별도 행으로 먼저 고친다. 수정 순서가 의존하면 순서를 적는다.
- 서버(GAS)는 응답 칸을 추가만 한다(이름 변경·삭제 금지). 배포는 기존 배포 편집 → 새 버전.
- 새 함수는 CLAUDE.md의 모듈 규칙을 따른다(ModFollowUp 신규는 ModFollowUp4).
- 코드는 **사용자 승인 후**에 쓴다. 형식은 CLAUDE.md "코드 제공 형식"을 따른다(수정 전/후 쌍, 유일 앵커 한 줄, 매칭 개수 검증).
- 수정 후 같은 영역을 다시 점검해 옛 코드 0건·새 코드 개수를 확인한다.

## 알려진 함정
- 인코딩: VBA 내보내기는 CP949라 UTF-8로 읽으면 한글이 깨진다 → prep.py 변환본만 읽는다.
- 검색 도구는 숨김·.gitignore 폴더를 건너뛴다 → 변환본 폴더 이름을 `audit_work`(숨김·ignore 아님)로 둔다. 대신 이 폴더를 커밋하지 않는다(`git add`는 경로를 지정해서만).
- 줄 번호: 내보낸 파일의 머리말(Attribute 등) 때문에 VBA 편집기와 어긋난다 → 항상 함수명으로 위치를 말한다.
- 대형 모듈(수만 줄): 한 에이전트에 통째로 주면 컨텍스트가 터진다 → 조각 분할.
- 에이전트는 지침을 모른다 → 브리프에서 CLAUDE.md 규칙 요약을 읽게 한다.
- 토큰 비용은 에이전트 수에 비례한다 → 영역 지정, 전체는 확인 후.
- 같은 가설을 여러 에이전트에 주면 확증 편향 → 가설은 나눠서 준다.
