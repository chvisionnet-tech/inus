# INUS 다중 에이전트 점검

## 역할
- **조율자(메인 세션)**: 영역 지정, 브리프 작성, 결과 합치기, [치명] 재확인, 수정 소유권 배정. 수정은 조율자만 한다.
- **영역 에이전트**: 자기 영역만 읽고 보고한다. 파일을 수정하지 않는다.

## 원칙
1. 에이전트는 이 대화를 모른다. 브리프에 목표, 범위, 찾을 것, 보고 형식을 모두 적는다.
2. 읽기 전용. 에이전트는 Edit/Write를 쓰지 않는다.
3. 판정은 증거로만 한다. 파일·함수·줄 번호와 원문 한 줄이 없는 판정은 무효로 본다.
4. "확인불가"를 허용한다. 억지 판정보다 낫다.
5. 영역 밖 의심은 "교차 확인 요청"으로만 적는다. 직접 읽지 않는다.
6. [치명]은 조율자가 원문 줄을 직접 열어 재확인한 뒤에만 수정 대상으로 올린다.
7. 수정은 파일·함수 단위로 소유자 1명. 공용 헬퍼는 먼저 따로 고친다.

## 영역 지도
대상 파일 목록이 확정되지 않았으면 먼저 사용자에게 확인한다. 아래는 기본 틀이다.

| 영역 | 주요 대상 | 중점 |
|---|---|---|
| 결제 | 메인 GAS 결제 부분, 결제창, 결제 신호 | 중복 처리, 상태 꼬임, 서명·위변조 확인, 실패 복구 |
| 로그인·인증 | INUS_SIG 서명, 폰 키, 1인 한도, 그룹 권한 | 서명 우회, 키 노출, 토큰 만료 |
| 메인 GAS | Code.gs, Quota.gs, dblink.gs | 속성 읽기·쓰기 횟수, try 밖 호출, 한도, 락 안 외부호출 |
| 영업 GAS | 영업목록, 폰 목록, 현장 문자 | 시트 행 증가, 락 없는 동시 쓰기 |
| AI 중계 | GptRelayBody, FU_RelayPick, 모델 매핑 | 빈 응답 폴백, 태그 누락, 직접 호출, 키 노출 |
| VBA 미니창 엔진 | ModFollowUp1~4 | 타이머 중복, 신호파일 삭제, 창 중복, 줄수 한계 |
| VBA 데이터 동기화 | 영업상태 txt, 시트 쓰기, ModMobileSync | 동시 저장 충돌, 읽기 실패 시 삭제 |
| 홈페이지·폰 | s.html, route.html, leader.html, _worker.js | 캐시 번호, 옛 호환 깨짐, 목록 토큰 |

교차 점검(영역 여럿에 걸친 항목, 필요 시 별도 에이전트):
- 키·URL 노출 전수 (엑셀 원본이 공개 주소로 배포되므로 최우선)
- 부하: 요청 1회당 속성·외부호출·시트 읽기 수, 사용자 1,000명 기준 하루 합계
- 백업·복구 경로
- 개인정보가 로그·공유 파일에 남는지
- 업데이트 파일 무결성
- 날짜 경계(자정, 월초, 1월 1일) 리셋

## 절차
1. **영역 지도 확정**: 요청된 영역과 실제 파일 목록을 맞춘다. 파일이 없으면 요청한다.
2. **브리프 작성**: 아래 템플릿으로 영역마다 작성한다.
3. **병렬 실행**: 영역 에이전트를 한 번에 띄운다. 영역이 많으면 결제·로그인 같은 핵심부터 우선한다.
4. **합치기**: 중복을 제거하고, 영역끼리 연결된 결함을 찾는다.
5. **재확인**: [치명]은 원문을 직접 연다. 판정이 틀리면 등급을 내린다.
6. **수정 범위 확정**: 파일·함수별 소유자, 순서, 공용 헬퍼 먼저 여부를 표로 적는다.
7. **보고**: 아래 형식으로 사용자에게 준다. 수정 코드는 사용자가 승인한 뒤에만 쓴다.

## 브리프 템플릿
```
[목표] <영역명>에서 오류·함정·결함을 찾아 보고. 수정하지 말 것.
[범위] <파일 경로와 함수 경계>. 이 밖은 읽지 말 것.
[찾을 것]
- <영역 중점 항목>
- 규칙 위반 잔재: alert/MsgBox/confirm, 한글 ChrW 변환, Open For Output, .Visible로 HTA 판단, 1024자 초과
[보고 형식]
- 위치: 파일 / 함수 / 줄 번호 / 원문 한 줄
- 실패 시나리오: 어떤 입력이나 상황에서 무엇이 틀어지는지 한 줄
- 등급: [치명] 먹통·데이터 손실·보안 / [주의] 조건부 / [개선]
- 확인: 확인됨 / 확인불가(이유)
- 없으면 "치명·주의 없음" 한 줄
[교차 확인 요청] 범위 밖 의심은 여기에만 적는다.
```

## 최종 보고 형식
- 영역별 건수 표
- [치명]: 위치, 원문, 재확인 결과, 수정 방향
- [주의]: 조건, 수정안
- [개선]: 필수/선택 구분
- 확인불가 항목과 필요한 파일
- 수정 소유권 표와 순서

## 주의
- 점검 한 번에 토큰 비용이 영역 수만큼 든다. 전체 점검은 필요할 때만 한다.
- 지침 파일의 세부 규칙(모달, 타이머, 신호파일, 주석 분량 등)은 사용자 지침을 따른다. 이 스킬에 복사하지 않는다.
- 비밀값(키, 토큰)은 보고에 그대로 적지 말고 앞뒤 일부만 마스킹한다.
